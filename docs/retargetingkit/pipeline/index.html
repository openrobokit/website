Concepts

Pipeline

RetargetingKit connects a motion source, a retargeter, and one or more targets. RoboKit provides the robot models and optimization tools used by the solvers.

Humanoid retargeting produces a base pose and joint command. Targets display the motion or send it to robot hardware and SONIC. ArmHandFrame synchronizes wrist and finger observations from one source; the runtime sends its arm and hand frames through their respective solvers. SONIC forwards humanoid commands to a separate control process for simulation or G1 hardware.

Three stages

StageResponsibilityExamples
SourceConvert device data or a recording into a canonical frameVision Pro, Manus, PICO, BVH
RetargeterMap human motion to robot jointsArm IK, hand optimization, neural hand, humanoid
TargetDisplay or send the resultViser, robot hardware, SONIC transport

A named rig supplies the matching source, solver, robot, and connection settings. The runtime builds them and runs the control loop. Start with a named rig for a complete workflow.

The diagram covers the canonical retargeting paths. Quest 3 has a standalone controller workflow. The PICO body-and-hands rig adds B/Y button commands for Inspire hand opening and closing alongside the body retargeter.

Shared data

Frames describe human motion. Commands describe a single solved robot pose. The source handles device axes and joint ordering before a retargeter receives the frame.

Hands use wrist-local MANO-21 keypoints; arms use world-frame wrist poses; bodies use named joint poses in a Z-up world frame. See Canonical frames for shapes and units.

One loop

For an initialized hand source, matching retargeter, and joint-position target:

python
frame = source.get_frame()
if frame is not None:
    command = retargeter.solve(frame)
    target.set_qpos(command.qpos)

Humanoid runtimes call target.set_command(command) so the target receives the base pose together with the joints. The runtime also owns startup and cleanup; the snippet shows only one update.

See Interfaces to build a custom pipeline, or RoboKit's robot model for the underlying kinematics.
