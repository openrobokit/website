User Guide

The Full Pipeline (launch.py)

scripts/launch.py turns a set of scene descriptions into a trained grasp policy. One experiment name selects an ExperimentConfig whose steps run in order: render point-cloud observations, synthesize and validate grasps, join both into a training dataset, and train an open-loop policy.

This tutorial explains what each stage does and how data flows between them. For stage deep-dives see the grasp_optim tutorial and the training tutorial; for every parameter see the config reference.

Overview

The default steps are ("render_data", "optimize_grasps", "process_sim_data", "train"). Observations and actions are produced independently from the same scene descriptions, then joined per scene.

  • robot_config decides what the optimizer outputs: a floating hand yields floating grasps, an arm+hand robot yields fixed-base grasps. The GraspTrajBuilder filters them, optionally IK-converts floating grasps onto the fixed robot (convert_to_fixed=True), and plans the grasp trajectory; the Evaluator keeps only grasps that survive a sim rollout.
  • Every stage writes a completion marker next to its output (.render_complete, .optim_complete, ...). A later launch skips any stage whose marker exists, so an interrupted pipeline resumes where it stopped.

Quick Start

Prerequisites: uv sync --extra maniskill --extra spconv, CUDA GPUs. Assets (scenes, object meshes, robot URDFs) download automatically on first use. Experiments live in src/graspkit/configs/experiment/ and are registered by name in its __init__.py.

shell
# Full pipeline on 4 GPUs
uv run scripts/launch.py xhand_right_dex1b_v0_5_mini_tabletop --gpus 0,1,2,3

# Run a subset of steps; any nested config field is a CLI flag through tyro
uv run scripts/launch.py xhand_right_dex1b_v0_5_mini_tabletop --steps optimize_grasps \
  --grasp_optim.num_attempts 2

# Rerun from a step: deletes that step's marker + output and everything downstream
uv run scripts/launch.py xhand_right_dex1b_v0_5_mini_tabletop --restart-from process_sim_data

# Append mode: keep the restart step's output, delete only its marker (top up grasps)
uv run scripts/launch.py xhand_right_dex1b_v0_5_mini_tabletop \
  --restart-from optimize_grasps --append

Renderer -> Point-Cloud Observations

Renders every scene through the calibrated real camera so training observations match deployment.

flowchart TD SD[(scene descriptions)] CALIB[(camera calibration<br/>extrinsic + intrinsic .json)] CAM[Per-scene camera poses<br/>fixed: calibrated view<br/>sampled: jittered views + look-at] REN[Renderer] SEG[Segmented object points] VIS[Object-visibility view filter<br/>sampled mode only] OUT[(rendered_data_path/scene_id.h5)] SD --> CAM CALIB --> CAM CAM --> REN --> SEG SEG -->|fixed| OUT SEG -->|sampled| VIS --> OUT

The calibrated extrinsic is anchored to the fixed-base robot's base pose (camera_frame="robot") or used as-is ("world"). camera_mode="fixed" saves one view per scene; "sampled" renders camera_sample_num_views jittered views and keeps every view where the target object projects into the image (multi-view augmentation). Key config: renderer (RendererConfig).

An optional sample_point_cloud step exists for experiments that want full object point clouds sampled directly from the meshes instead of rendered ones; no registered experiment currently uses it.

GraspOptimizer -> Grasp Synthesis and Validation

Synthesizes grasps per scene and keeps only those that survive filtering, motion planning, and a physics stress test. See the grasp_optim tutorial for the components and the algorithm concepts for the two optimizer backends.

%%{init: {"flowchart": {"curve": "linear"}}}%% flowchart LR SD([scene description]) --> OPT[grasp optimizer] OPT --> GP["3 frame grasp poses<br/>(floating/fixed base)"] GP --> TB[traj builder] TB --> GT([grasp traj]) GT --> EV[simulation evaluator] EV --> GP GP -- successful grasps --> OG([optimized grasps]) style OPT fill:#ffe680,stroke:#b38f00 style TB fill:#ffe680,stroke:#b38f00 style EV fill:#ffe680,stroke:#b38f00 linkStyle 6 stroke:#2e9e44,color:#2e9e44

The stage loops num_attempts passes with work stealing: a scene stays to-do while its file holds fewer than min_grasps_threshold grasps, so later passes top up hard scenes. Each batch runs optimize -> filter + plan -> sim eval, then appends the surviving pre/grasp/post configurations. Key config: grasp_optim (GraspOptimConfig, evaluator nested inside) and traj_builder (GraspTrajBuilderConfig).

process_sim_data —> Join Observations and Actions

Joins the two upstream outputs per scene ID into one training HDF5. Scenes missing either side are dropped.

flowchart TD PC[(rendered pts)] GR[(succ grasp poses)] CE["ContactExtractor (optional)"] GW[graspness weight] OUT[(processed sim data<br/>processed_data_path .h5)] PC --> OUT GR --> OUT GR --> CE --> GW --> OUT

Actions stack the three saved configurations per grasp; meta/action_mean and meta/action_std normalize them during training. With enable_contact_extraction=True each scene also gets per-point graspness weights. See data_format.md.

Trainer — Policy Learning

Learns an open-loop policy mapping one scene point cloud to pre-grasp, grasp, and post-grasp configurations. See the training tutorial.

flowchart TD DS[(Dex1B dataset<br/>processed_data_path .h5)] POL[GraspPolicy<br/>point-cloud encoder + CVAE] TB[GraspTrajBuilder] EV[Evaluator] CKPT[(ckpt<br/>logs/train/name)] DS --> POL --> TB --> EV --> CKPT
  • Every eval_freq iterations, predicted grasps go through the same GraspTrajBuilder path as data optimization (filters + motion planning) before rolling out in the evaluator env.
  • The policy can also be trained on floating grasps and evaluated on the fixed-base robot: with traj_builder.convert_to_fixed=True the builder IK-converts the predicted floating grasps onto the arm and the evaluator rolls out the fixed-base trajectories (see xhand_right_dex1b_v0_5_mini_tabletop_fixed_eval). Key config: dataset (DatasetConfig), agent (GraspPolicyConfig), trainer (TrainerConfig).
