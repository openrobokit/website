Grasp optimizer algorithm and runtime parameters, with hand-independent defaults.

The config of the optimize_grasps stage (ExperimentConfig.grasp_optim); every field is a CLI flag, e.g. --grasp_optim.num_iters 2000. The annealing fields drive warp_gd only and the lm_* fields warp_lm only. The init-sampler fields feed stages/grasp_optim/sampler.py; the runtime fields feed optimize_pipeline.py, not a bare optimize() call.

attribute[source]
GraspOptimConfig.num_iters: int = 6000

Annealing iterations (warp_gd). Each replays one CUDA graph; fewer trade grasp quality for speed, and 2000 suits smoke tests.

attribute[source]
GraspOptimConfig.num_contact_points: int = 4

Active contact points per grasp, drawn from the robot's contact candidates; they parameterize the distance and force-closure terms. 4-5 fits most five-finger hands.

attribute[source]
GraspOptimConfig.switch_possibility: float = 0.5

Per-grasp probability, each iteration, of re-drawing the whole contact set; the Metropolis test accepts or rejects it together with the pose step.

attribute[source]
GraspOptimConfig.mu: float = 0.98

RMSprop weight on the current squared gradient, ema = mu * g^2 + (1 - mu) * ema. Near 1 the step approaches the gradient's sign times step_size.

attribute[source]
GraspOptimConfig.step_size: float = 0.005

Base RMSprop step; the effective step is step_size * temperature_decay^(t // stepsize_period).

attribute[source]
GraspOptimConfig.stepsize_period: int = 50

Iterations between step-size decays.

attribute[source]
GraspOptimConfig.starting_temperature: float = 18.0

Initial Metropolis temperature T: a proposal that worsens the energy by d is still accepted with probability exp(-d / T).

attribute[source]
GraspOptimConfig.annealing_period: int = 30

Iterations per temperature decay, T = starting_temperature * temperature_decay^(t // annealing_period).

attribute[source]
GraspOptimConfig.temperature_decay: float = 0.95

Decay factor shared by the temperature and step-size schedules; closer to 1 cools slower and explores more.

attribute[source]
GraspOptimConfig.spen_threshold: float = 0.01

Self-collision margin (m) between sphere/capsule pairs; 2 cm pinned the middle finger of most hands off the object.

attribute[source]
GraspOptimConfig.spen_representation: Literal['capsule', 'sphere'] = 'sphere'

Self-collision geometry for warp_gd: per-link capsules or the collision spheres. warp_lm always uses capsules.

attribute[source]
GraspOptimConfig.w_fc: float = 1.0

Force-closure weight: the active contact normals must balance external wrenches. A zero weight disables any term.

attribute[source]
GraspOptimConfig.w_dis: float = 100.0

Weight pulling each active contact point onto the target surface.

attribute[source]
GraspOptimConfig.w_fingertip_dis: float = 0.0

Weight of the fingertip term (warp_gd only; requires fingertip links set): each fingertip link's closest collision sphere is drawn onto the object. 0 disables; a hand should touch without it, this is a last resort.

attribute[source]
GraspOptimConfig.w_pen: float = 100.0

warp_gd scene-penetration weight: hand collision spheres against the target and table, with a fixed 5 mm margin. warp_lm uses lm_w_pen.

attribute[source]
GraspOptimConfig.w_spen: float = 10.0

Self-penetration weight between robot links; zero skips building the term.

attribute[source]
GraspOptimConfig.w_joints: float = 1.0

warp_gd joint-limit weight; q is also clamped to its limits every iteration. warp_lm uses lm_w_joints.

attribute[source]
GraspOptimConfig.w_angle_z: float = 0.0

Weight of the hand-orientation prior (HandUpAngleTask, both backends).

attribute[source]
GraspOptimConfig.angle_z_min: float = math.pi / 2

Minimum angle between the hand-up axis and world +z; tabletop configs use it to forbid underhand grasps.

attribute[source]
GraspOptimConfig.hand_axis: Optional[HandAxis] = None

Hand-axis cone filter on init samples: which hand_coord_spec axis to check, after IK for fixed-base samplers. None disables it. The cone on optimized grasps lives on GraspTrajBuilderConfig.

attribute[source]

GraspOptimConfig.optimizer_backend: Literal['warp_gd', 'warp_lm'] = 'warp_gd'

warp_gd: simulated-annealing gradient descent for floating or fixed-base robots. warp_lm: multi-seed Levenberg-Marquardt, floating base only, typically 2-3x faster and needs fingertip links; to target an arm, set enable_ik_scoring and let GraspTrajBuilder IK-convert.
