Batched motion planning with goal IK, trajectory optimization stages, and retry.

Lifecycle

  1. __init__ copies configuration and constructs goal IK, the optimizer stages, and their retiming.
  2. warmup(batch_size) fixes the batch size and allocates all batch-shaped state.
  3. solve_offline(...), which solve_offline_numpy and solve_offline_torch wrap, places the waypoints, builds candidates, solves and retries trajectories, then retimes them with the last stage's retime and computes motion_time.
  4. solve_online(...) runs a fresh gradient solve with executed-history smoothing, or updates the retained MPPI action distribution.

fixed_relative_poses: Optional[Sequence[FixedRelativePose]] = None
) -> MotionPlanResult[wp.array]

Plan batched Warp trajectories through waypoints, start first and goal last; the NumPy and Torch APIs wrap it.

Lifecycle

  1. Parse segments: each segment's world collision flag, fixed duration and lock.
  2. Solve waypoint IK: each pose but a final goal by goal IK (scene collision, no self collision), resting at its neighbors' blend.
  3. Create split: each segment's frames by its duration, else evenly, then the locked frames and collision.
  4. Solve: _solve_offline_attempt with retries, one CUDA graph under cuda_graph="solve" but for durations; it builds each guess's goal by goal IK, its later poses' answers nearest its neighbors' blend, and straight lines through its waypoints, on frames resplit by the time each line needs; after the first stage, several segments resplit their frames again.
  5. Retime: every plan under the last stage's retime, its fixed segments held still, and its motion time.
Parameters
waypointsSequence[Union[wp.array, Dict[str, wp.array]]]required

Ordered list of at least two: joint arrays (batch, dofs) in robot.spec.actuated_joint_names order, wp_vec7 arrays (batch,) or (batch, target links) posing the target links, or dicts of target link names to wp_vec7 (batch,) posing some of them (other keys are ignored). A link a dict leaves out is free at its frame, so each link reaches its own waypoints in turn: the first guess keeps it at its pose of the waypoint before (blended toward any later joint waypoint; a start pose's at seed_q or the next joint waypoint, one needed), and the stages move it from there only as their costs pull. Every link passes each waypoint at the same instant, and the goal names all. An inner waypoint holds the links it names at its joints or IK answer, contact included.

start_T_world_baseOptional[wp.array]= None

A floating base's start poses, wp_vec7 (batch,); such plans take a start and a goal.

seed_qOptional[wp.array]= None

Optional IK seed: the goal IK's initialization, or the rest of a pose waypoint before any joint one.

scene_indicesOptional[wp.array]= None

Optional scene index per batch row; defaults to zero.

segment_check_collisionOptional[Sequence[bool]]= None

One flag per segment (waypoint i to i + 1); False drops world collision there (self collision stays), and from the checks of anchors only such segments touch, e.g. a contact. Defaults to all True. Every segment_* and waypoint_* list applies to all batch rows alike.

segment_fixed_durationOptional[Sequence[Optional[float]]]= None

Seconds per segment, or None to let the planner time it. A duration gives the segment round(duration / dt) frames (at least two) in the solve, keeps them through the resplit and is its time in interpolate; None segments share the rest of num_timesteps, which the durations must fit.

segment_lockedOptional[Sequence[bool]]= None

One flag per segment; True keeps its frames on the straight joint-space line between its waypoints (the tool's path between them is not straight), whatever it passes through, and holds the links both its waypoints name.

attached_objectsOptional[Sequence[AttachedObject]]= None

Objects the robot carries, on the spheres max_attached_spheres reserves on the target link each one's link is rigid with: checked by world and self collision over their segments (an inner waypoint: those both its segments carry), in the stages, their scores and waypoint and goal IK.

fixed_relative_posesOptional[Sequence[FixedRelativePose]]= None

Link pairs whose relative pose the gradient stages hold over their segments, at most max_fixed_relative_poses.

Returns
MotionPlanResult[wp.array]

last and only their rows return; more raise ValueError("Batch size mismatch").

method[source]
MotionPlanResult.interpolate(
dt: float,
speed_scale: float = 1.0
) -> ArrayT

Joint trajectories sampled every dt (s) or slightly less across motion_time.

Each segment between waypoints spreads ceil(its time / dt) steps evenly over its frames, so every waypoint is a sample; a plan then holds its last frame, so a batch shares one length. A segment with a fixed segment_fixed_duration takes that time; the others run at the plan's retimed step or segment_duration.

Example

python
>>> import numpy as np
>>> q_traj = np.array([[[0.0], [1.0], [2.0]]], np.float32)
>>> MotionPlanResult(q_traj, motion_time=np.array([1.0], np.float32)).interpolate(0.25)[0, :, 0]
array([0. , 0.5, 1. , 1.5, 2. ], dtype=float32)

Objective configuration

GradientTrajectoryOptimizerConfig and MppiTrajectoryOptimizerConfig accept terms, a list of ResidualTask templates. Objective weights and cost options are task constructor parameters. Use config.task(name) to retrieve a named task; for TrajectoryTask, configure its dense_task. deepcopy(config) creates an independent preset whose task attributes can be assigned directly. Config-level cost-weight arguments have been removed. IK objectives are supplied through MotionPlannerConfig.goal_ik.
